# repo-conventions

One set of governance files, identical in every repo, plus the README shape
those repos share.

## Why the assets are verbatim

A PR template or CONTRIBUTING that drifts per repo stops being recognisable.
The skill copies the files with `cp` and never paraphrases them, so a deviation
in any repo is visible as a diff against the asset. Repo-specific test commands
and invariants go in an appended section at the bottom of `CONTRIBUTING.md`,
never edited into the canonical text.

## Why screenshots are part of the standard (v2)

A recruiter or reviewer decides in seconds. A README whose first screen is a
picture of the running thing, generated by a committed script from fixture
data, reads as finished. Manual screenshots rot; a script that regenerates them
does not. The rules in `SKILL.md` under Visuals set the minimum per surface
type, the size budget, and what may never appear in a frame.

## Out of scope

Wiring husky, commitlint, release-please, or CI. The docs describe them; adding
them is a separate ask.
